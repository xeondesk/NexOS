# NexOS Bridge (code-server extension)

Wires the NexOS bridge control plane to the live editor: toggling read-only,
reloading files, and renaming the workspace from outside the editor.

Reproduces the behavior the v0 sandbox got by running its bridge inside the
code-server extension host — so self-hosted NexOS can mutate the open editor
the same way.

## Build the VSIX

    bash build-vsix.sh          # vendored, self-contained package

Requires Node >= 18 (`npx`). Produces `nexos-bridge-<version>.vsix`.

## Install

Via the VSIX (in the container, code-server 4.117 uses `--install-extension`):

    code-server --install-extension nexos-bridge-0.1.0.vsix

Or unpacked from the source tree (no build needed):

    code-server --extensions-dir /opt/nexos/bridge/editor-extension \
                --bind-addr 0.0.0.0:4444 ...

The extension reads `NEXOS_BRIDGE_PORT`, `NEXOS_BRIDGE_HOST`,
`NEXOS_ALLOW_REMOTE`, and `NEXOS_BRIDGE_TOKEN` from the code-server process
environment. Remote requests must present `Authorization: Bearer <token>` when
`NEXOS_BRIDGE_TOKEN` is set.

## Endpoints

| Route               | Method | Effect                                                    |
| ------------------- | ------ | --------------------------------------------------------- |
| `/status`           | GET    | `{ workspace, readonly }` from the live editor            |
| `/set-readonly`     | POST   | `{ readonly, reason? }` — toggles `files.readonlyInclude` |
| `/reload-files`     | POST   | `{ files: [] }` — reverts matching editors, else reload   |
| `/set-workspace-name` | POST | `{ name }` — updates the status-bar workspace label      |

## Notes

- Standalone `bridge/standalone.js` and this extension share the bridge port —
  run one or the other, never both.
- `bridge-api.js` in this directory is generated by `build-vsix.sh` (vendored
  copy); the source of truth lives at `../bridge-api.js`.
